# Day 1 · 执行上下文与作用域链

```
全局执行上下文
├── 变量环境（对象环境记录）→ 绑定到 globalThis（window）
│   └── var a、function foo
└── 词法环境（声明式环境记录）→ 不挂 window
    └── let b、const c、class D
    
var a = 1;
let b = 2;
console.log(window.a); // 1
console.log(window.b); // undefined
```

1. ### 全局作用域、函数作用域、块级作用域，分别在什么时候创建？

   - #### 全局作用域

     - 在代码开始执行前（引擎初始化阶段）就被创建了，它是唯一一个贯穿整个程序生命周期的环境
     - **全局作用域下，函数声明和 var 一样，会挂到全局对象 window**

   - #### 函数作用域

     - 在函数**被调用（执行）**时创建，更准确地说，当执行流进入一个函数时，引擎会为其创建一个新的执行上下文，随之创建它的局部作用域。

   - #### 块级作用域

     - 在代码执行到该代码块（{}）时创建。也就是遇到if for while，或者单纯的{}包裹的代码时，引擎会为其创建一个独立的环境，用来存放 let 和 const 声明的变量

2. ### 什么是词法作用域？为什么 JS 不是动态作用域？

   - #### 词法作用域

     - 又叫静态作用域。变量在哪里能被访问，是由代码在编写时的物理位置（词法结构）决定的，而不是由代码在哪里诶调用决定的

   - #### 为什么 JS 不是动态作用域

     - 动态作用域是指在代码运行时，根据函数被调用的位置来决定变量查找。JS采用词法作用域。

     ```js
     var a = 1;
     function foo() { console.log(a); }
     function bar() {
       var a = 2;
       foo(); // 在 bar 里面调用 foo
     }
     bar(); // 输出结果是 1，而不是 2！
     ```

     

3. ### 执行上下文里有什么？`var` 和 `let` 的位置有什么不同？

   1. #### 词法环境

      - 负责标识符解析，查找变量实际去的地方

   2. #### 变量环境

      - 一种特殊的词法环境，专门用来登记var声明的变量和函数声明

   3. #### ThisBinding

      - 确定当前代码中 this 的指向

4. ### var 和 let 的位置有什么不同

   - #### 在全局代码或函数代码中

     - var 声明的变量，存放在“变量环境”中
     - let 和 const 声明的变量，存放在词法环境中

   - #### 三大核心区别

     - 变量提升

       - `var` 会被登记到变量环境，并在代码执行前初始化为 `undefined`，所以你在声明前访问它会得到 `undefined`。
       - `let` 会被登记到词法环境，但**不会被初始化**。在声明语句执行之前，访问它会直接报错（ReferenceError），这个现象叫**暂时性死区（TDZ）**

     - 作用域范围

       - `var` 在变量环境中，变量环境对应的是函数作用域或全局作用域，所以 `var` 会穿透 `if`、`for` 等块，属于函数级别。

       - `let` 在词法环境中，而词法环境是可以嵌套的。当遇到 `{}` 块级作用域时，引擎会创建一个新的词法环境嵌套进去。因此 `let` 被限制在块级内部。

         - ```js
           // 同一个作用域里，let 重复声明才报错；嵌套作用域里，内层声明会遮蔽（shadow）外层，合法
           for (let i = 0; i < 3; i++) {
             let i = 'abc';   // 内层块作用域，遮蔽循环头的 i
             console.log(i);  // 'abc'
           }
           ```

     - 重复声明

       - 引擎允许变量环境中的 `var` 重复覆盖声明
       - 但在词法环境中，语法规定不允许出现同名标识符，所以 `let` 不能重复声明

     - **一句话总结**：`var` 存在“变量环境”里，比较粗放（提升到顶部，不管块作用域）；`let` 存在“词法环境”里，比较严谨（有暂时性死区，严格束缚在当前大括号里）。
